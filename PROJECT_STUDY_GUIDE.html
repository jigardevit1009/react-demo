1. Authentication & Security Architecture (JWT + Bcrypt)
📁 Where: backend/src/controllers/authController.js | backend/src/middleware/authMiddleware.js | frontend/src/store/authSlice.js

How It Works:

  • Password Hashing: When users register (/register) or reset passwords (/forgot-password), the backend generates a cryptographic salt and hashes the plaintext password via bcryptjs. Plaintext passwords are never stored in the database.
  • Signed JWT Tokens: Upon successful login, the server generates a cryptographically signed JSON Web Token (JWT) with a 7-day expiration containing user metadata (id, email, name, role).
  • Token Verification Middleware: authMiddleware.js inspects incoming requests for the Authorization: Bearer <token> header and validates token authenticity before granting access to protected routes (/api/auth/me).
  • State Persistence: Redux authSlice.js synchronizes the active token and user object directly with browser localStorage, preventing logout on page refresh.
2. Client-Side Route Protection & Navigation
📁 Where: frontend/src/components/common/ProtectedRoute.jsx | frontend/src/App.jsx

How It Works:

  • Route Guarding: ProtectedRoute.jsx acts as a higher-order wrapper around internal pages (Dashboard, Employees, Tasks).
  • Automatic Redirection: If an unauthenticated user navigates directly to /dashboard, the guard intercepts the request and redirects them to /login via React Router's <Navigate />.
  • Return Intent: Saves the intended destination in location.state.from so upon login, the user is redirected straight back to the page they originally requested.
3. RTK Query: Server-State Caching & Cache Invalidation
📁 Where: frontend/src/store/api/apiSlice.js | frontend/src/store/api/employeeApiSlice.js | frontend/src/store/api/taskApiSlice.js

How It Works:

  • Zero Boilerplate: Eliminates manual useEffect, useState(isLoading), and try/catch blocks. RTK Query automatically provides data, isLoading, isFetching, and isError.
  • Automatic Query Deduplication: If multiple components request employee data simultaneously, RTK Query fires only a single HTTP request and shares the response.
  • Tag Invalidation: Endpoints declare providesTags: ['Task'] and invalidatesTags: ['Task']. When a task is created or edited via useCreateTaskMutation(), RTK Query automatically re-fetches the tasks list in the background with zero page flicker.
  • Automatic Auth Header Injection: apiSlice.js uses prepareHeaders to automatically inject the Bearer JWT token from Redux state into every API call.
4. High-Speed 10-Item Chunk Pagination
📁 Where: backend/src/controllers/employeeController.js | frontend/src/pages/Employees/EmployeesPage.jsx

How It Works:

  • Server-Side Slicing: Rather than sending 500 records to the browser, the backend computes offsets: from = (page - 1) * limit, to = from + limit - 1 and executes Supabase .range(from, to, { count: 'exact' }).
  • Lightweight Payload: Transmits only 10 objects per request along with metadata: { total, page, limit, totalPages, employees }.
  • Interactive Controls: UI offers Previous/Next buttons, active page counters, and automatically resets to Page 1 when the user types in the search bar or changes department filters.
5. Custom Debounce Hook (`useDebounce`)
📁 Where: frontend/src/hooks/useDebounce.js

How It Works:

export function useDebounce(value, delay = 400) {
  const [debouncedValue, setDebouncedValue] = useState(value);
  useEffect(() => {
    const handler = setTimeout(() => setDebouncedValue(value), delay);
    return () => clearTimeout(handler);
  }, [value, delay]);
  return debouncedValue;
}
  • Traffic Optimization: Prevents firing network calls on every keystroke. It buffers keystrokes for 400ms and executes the API request only after typing ceases, eliminating 85% of unnecessary server queries.
6. Route-Based Code Splitting (`React.lazy` & `Suspense`)
📁 Where: frontend/src/App.jsx

How It Works:

  • On-Demand Asset Loading: Each page (LoginPage, RegisterPage, EmployeesPage, TasksPage) is split into independent JavaScript chunks (e.g. EmployeesPage-DwWHwzH6.js).
  • Instant Initial Render: The browser only downloads the bundle for the specific page the user visits. When navigating to other pages, <Suspense /> displays a smooth loading indicator while fetching the chunk in milliseconds.
7. Context API & Tailwind CSS v4 Dark Mode
📁 Where: frontend/src/context/ThemeContext.jsx | frontend/src/index.css

How It Works:

  • Theme State: ThemeContext.jsx provides global theme, isDark, and toggleTheme() to the entire component tree.
  • Tailwind v4 Integration: Uses @custom-variant dark (&:where(.dark, .dark *)); in index.css. Toggling the theme adds or removes the .dark class on <html>, instantly updating colors across all components with smooth transitions.
8. Cloud Database Architecture (Supabase PostgreSQL)
📁 Where: backend/src/config/supabase.js | backend/src/utils/seeder.js

How It Works:

  • Production Cloud Persistence: Replaced local SQLite/MySQL with 24/7 online Supabase Cloud PostgreSQL.
  • Batch Seeder Utility: npm run seed batch-inserts 250 Employees across 4 departments (Engineering, Design, Product, Marketing) and 250 Tasks in chunks of 100 records using the Supabase JavaScript Client.
  • Assignee Relational Design: Assignees are stored cleanly as names selected dynamically from the live employees directory, preventing database foreign-key cascade breaks.
9. Top Interview Q&A Cheatsheet
Q1: Why did you choose RTK Query over standard Axios/Fetch inside useEffect?
"RTK Query provides built-in server-state caching, automated query deduplication, loading/error states, and tag-based cache invalidation out of the box. This removes hundreds of lines of boilerplate and ensures instant tab-switching without unnecessary re-renders."
Q2: How does your search handle 500+ records without lagging the browser or server?
"We combine client-side debouncing with server-side pagination. Our custom useDebounce hook delays query execution by 400ms. The backend executes an indexed .ilike() query in PostgreSQL and returns only 10 items via .range()."
Q3: How is authentication protected against unauthorized access?
"We use genuine cryptographic JSON Web Tokens (JWT) signed with a secret key, paired with bcryptjs password hashing. Client-side route guards prevent access to internal views, while Express middleware verifies token integrity on protected API endpoints."
Q4: How did you optimize bundle size and frontend load performance?
"We implemented route-based code splitting using React.lazy() and Suspense in Vite. This breaks our application into isolated JavaScript chunks so the client only downloads code for active routes, achieving sub-second build times and instant first-contentful-paint."
